Content cluster architecture

Design hub-and-spoke content systems with clear owners, internal links, and anti-cannibalization rules.

Direct answer: A content cluster is a hub page plus supporting spokes that each own a distinct query family and link back to the hub with descriptive anchors.

Hub requirements

  • Defines the topic in the first 100 words
  • Links to every active spoke
  • Holds commercial or primary educational intent

Spoke requirements

  • Answers one question or sub-intent completely
  • Links up to the hub and sideways to 2–4 siblings
  • Does not restate the hub’s primary keyword in the title as a clone

Link matrix (simple)

Hub → all spokes. Each spoke → hub + previous/next spoke + one systems page. Blog posts may act as temporary spokes until promoted or pruned.
